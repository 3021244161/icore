## 1. 实施概述

本文档是 v0.6 增强的落地实施记录，对照 [docs/12-v0.6-enhancement.md](12-v0.6-enhancement.md) 的方向性规划，逐一说明每个功能模块的实现位置、测试覆盖与验收状态。

v0.6 在 v0.5 的基础上引入 9 个功能增强与 5 个工程增强，新增 16 个 Python 模块、3 个示例工作流、9 套部署文件，测试基线从 v0.5 的 ~520 个提升至 **1121 passed + 2 skipped**。

## 6. 接线完成状态（2026-08-02 修复）

v0.6 初版存在"模块孤岛化"问题：代码完整、测试齐全，但 7 个模块从未被 API / executor / bootstrap 引用。经 code review 后已全部修复并接入生产路径：

| 模块 | 接线前状态 | 接线后状态 | 验证方式 |
|------|-----------|-----------|----------|
| **auth** | ❌ 完全未接入 | ✅ `create_auth_dependency` 挂到 `/invoke`；`/health`、`/metrics` 免鉴权；`/history` 挂 `history` 权限（admin/developer/viewer）；`/admin/dlq/*` 挂 `admin` 权限（仅 admin） | 无 key -> 401；viewer -> 403；admin -> 通过 |
| **observability** | ❌ 完全未接入 | ✅ `MetricsMiddleware` + `RequestIDMiddleware` 安装；`GET /metrics` 路由注册 | `curl /metrics` 返回 Prometheus 格式 |
| **persistence** | ❌ 完全未接入 | ✅ executor 每节点 `record_task_execution` + 每 wave `save_checkpoint`；`/invoke` `create_execution`/`complete_execution`/`fail_execution`；`GET /history` 端点 | `curl /history` 返回执行记录 |
| **DLQ** | ❌ 完全未接入 | ✅ executor 节点重试耗尽后 `dlq.enqueue`；`GET /admin/dlq/list` + `POST /admin/dlq/replay` 端点 | `curl /admin/dlq/list` 返回条目 |
| **semantic cache** | ❌ 完全未接入 | ✅ `ModelManager.set_semantic_cache()` + `get_adapter()` 用 `CachedModelAdapter` 包装 | `ICORE_CACHE_ENABLED=true` 启用 |
| **security** | ❌ 完全未接入 | ✅ `/invoke` 入口对 `params` 做 `InjectionDetector.detect`，命中返回 400 | 注入输入 -> 400 `PromptInjectionError` |
| **triggers** | ❌ 完全未接入 | ✅ `bootstrap.build_trigger_manager()` + lifespan `start_all()`/`stop_all()` | `ICORE_TRIGGERS_ENABLED=true` 启用 |
| **hot_reload TriggerManager** | ❌ docstring 承诺但无实现 | ✅ `HotReloadCoordinator` 加 `trigger_manager` 引用 + `_reload_triggers` 回调 | triggers.yaml 变化时 stop -> reload -> start |
| **supervisor trace** | 🟡 异常分支不写 trace | ✅ 子 agent 抛异常时也追加 trace 条目（含 `exception_type`） | trace 完整记录所有子 agent |

### 接线架构

```
bootstrap.create_production_app()
    │
    ├── build_observability() ──────────────> MetricsRegistry
    ├── build_auth_dependency() ───────────> FastAPI Depends
    ├── build_persistence_manager() ───────> WorkflowPersistenceManager
    ├── build_dlq() ───────────────────────> DeadLetterQueue
    ├── build_security() ──────────────────> InjectionDetector
    ├── build_trigger_manager() ──────────> TriggerManager
    ├── build_semantic_cache() ────────────> SemanticCache -> ModelManager.set_semantic_cache()
    │
    └── create_app(... all injected ...)
            │
            ├── app.add_middleware(MetricsMiddleware)
            ├── app.add_middleware(RequestIDMiddleware)
            ├── GET /metrics ──> prometheus_response(registry)（免鉴权）
            ├── GET /history ──[history 权限]──> persistence.get_history()
            ├── GET /admin/dlq/list ──[admin 权限]──> dlq.list()
            ├── POST /admin/dlq/replay ──[admin 权限]──> dlq.replay()
            ├── POST /invoke ──[auth dependency]──> ...
            │       ├── injection_detector.detect(workflow_name + params) ──> 400 if injection
            │       ├── persistence.create_execution()
            │       ├── workflow.execute(ctx, params, execution_id=...)
            │       │       └── executor.run(dag, ctx, params, execution_id=...)
            │       │               ├── _record_node() ──> persistence + dlq
            │       │               └── _save_checkpoint() ──> persistence
            │       └── persistence.complete/fail_execution()
            │
            └── lifespan: trigger_manager.start_all() / stop_all()
                          persistence.close() / dlq.close()
```
