## 1. 版本概述

### 1.1 版本对比

| 维度 | v0.4（当前） | v0.5（目标） |
|------|-------------|-------------|
| 数据存储 | PostgreSQL / Oracle / Hive / MySQL | **+ Milvus 向量库** |
| 结构化知识 | 无 | **+ 图引擎 / 知识图谱** |
| 文件处理 | 纯文本 | **+ 图片 / 视频 / 音频（多模态）** |
| 模型能力 | 纯文本 LLM（OpenAI 兼容） | **+ 多模态模型（GPT-4V / Claude Vision 等）** |
| 并发控制 | 代码实现但未接入 API | **接入 API + 增强** |
| 异常处理 | 基础 try/except + 日志 | **分级异常体系 + 熔断 + 降级 + 重试策略** |
| 冲突解决 | 无 | **分布式锁 + 乐观锁 + 幂等机制** |
| 系统健壮性 | 基础 | **优雅关闭 + 内存泄漏防护 + 健康探针 + 资源监控** |
| 测试覆盖 | core / engine(dag+executor) / api / examples | **+ db / models / services / concurrency** |

### 1.2 核心目标

1. **补齐企业级关键能力缺口：** 向量检索、知识图谱、多模态——这三个方向是当前 LLM 应用开发中最受关注的技术栈，简历项目必须覆盖
2. **工程健壮性达到生产可部署级别：** 熔断降级、冲突解决、优雅关闭、内存管理等，体现对分布式系统工程实践的理解
3. **预留扩展接口：** 每个新模块都设计抽象基类 + 适配器，方便替换底层实现（Milvus → Qdrant、Neo4j → ArangoDB 等）

## 3. 向量数据库集成 — Milvus

### 3.1 设计动机

- **RAG（检索增强生成）：** 将文档 Embedding 存入向量库，工作流中先检索相关片段再喂给 LLM，显著提升回答质量
- **语义搜索：** 对文本做语义相似度检索，底层模型通过 `multimodal_adapter.embed()` 生成向量
- **去重与聚类：** 对海量文本向量做相似度去重、聚类分析（如舆情聚类、文档去重）

### 3.2 接口抽象

```python
# icore/vectorstore/base_vectorstore.py

from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import Any, Optional

@dataclass
class VectorDocument:
    """向量化文档。"""
    id: str
    vector: list[float]
    metadata: dict[str, Any]
    text: Optional[str] = None

class BaseVectorStore(ABC):
    """向量存储抽象基类。

    Milvus / Qdrant / Pinecone / Chroma 等实现这个接口。
    TaskContext 注入具体实例，Task 通过接口操作。
    """

    @abstractmethod
    async def insert(
        self, collection: str, docs: list[VectorDocument]
    ) -> list[str]:
        """插入文档，返回 id 列表。"""
        ...

    @abstractmethod
    async def search(
        self,
        collection: str,
        query_vector: list[float],
        top_k: int = 10,
        filter_expr: Optional[str] = None,
    ) -> list[VectorDocument]:
        """向量相似度检索（ANN）。"""
        ...

    @abstractmethod
    async def delete(self, collection: str, ids: list[str]) -> int:
        """按 ID 删除文档。"""
        ...

    @abstractmethod
    async def create_collection(
        self, name: str, dim: int, index_type: str = "IVF_FLAT"
    ) -> None:
        """创建集合（含索引配置）。"""
        ...

    @abstractmethod
    async def drop_collection(self, name: str) -> None:
        """删除集合。"""
        ...

    @abstractmethod
    async def health_check(self) -> bool:
        """连通性检查。"""
        ...

    async def close(self) -> None:
        """释放连接资源。"""
        pass
```

## 4. 图引擎与知识图谱

### 4.1 设计动机

- **实体关系抽取 → 图谱构建：** 从非结构化文本中抽取实体与关系，构建知识图谱
- **图谱查询：** 支持 Cypher（Neo4j）或 Gremlin 查询，用于问答、推理
- **GraphRAG：** 结合图结构与向量检索，提升复杂问答准确率（如多跳推理）
- **可视化：** 拿图谱结果直接喂 Cytoscape.js / D3.js 前端渲染

### 4.2 接口抽象

```python
# icore/graphstore/base_graphstore.py

from dataclasses import dataclass
from abc import ABC, abstractmethod

@dataclass
class GraphNode:
    id: str
    labels: list[str]
    properties: dict[str, Any]

@dataclass
class GraphEdge:
    source_id: str
    target_id: str
    type: str
    properties: dict[str, Any]

class BaseGraphStore(ABC):
    """图存储抽象基类。

    Neo4j / ArangoDB / NetworkX / Amazon Neptune 实现此接口。
    """

    @abstractmethod
    async def upsert_nodes(self, nodes: list[GraphNode]) -> list[str]:
        """批量插入/更新节点，返回节点 id 列表。"""
        ...

    @abstractmethod
    async def upsert_edges(self, edges: list[GraphEdge]) -> None:
        """批量插入/更新边。"""
        ...

    @abstractmethod
    async def query(
        self, cypher: str, params: dict[str, Any] | None = None
    ) -> list[dict[str, Any]]:
        """执行 Cypher 查询（Neo4j 方言，其他适配器自行翻译）。"""
        ...

    @abstractmethod
    async def get_subgraph(
        self, node_ids: list[str], depth: int = 1
    ) -> dict[str, Any]:
        """获取以指定节点为中心的子图（深度可配置）。"""
        ...

    @abstractmethod
    async def delete_nodes(self, ids: list[str]) -> int:
        """删除节点（含关联边）。"""
        ...

    @abstractmethod
    async def health_check(self) -> bool:
        """连通性检查。"""
        ...

    async def close(self) -> None:
        pass
```

## 5. 多模态文件处理

### 5.1 设计动机

- 当前整个系统只能处理纯文本，但企业场景中存在大量图片（扫描件/截图）、音频（会议录音）、视频（监控/产品演示）数据
- 需要设计一套**抽象层 + 处理器适配器**，让 Task 可以统一获取 `MediaFile` 对象，而不用关心底层是本地文件还是对象存储 URL
- **预留接口：** 即使当前只实现本地文件 + HTTP URL 两种源，未来可扩展 S3/GCS/OSS

### 5.2 MediaFile 抽象

```python
# icore/media/base.py

from enum import Enum
from dataclasses import dataclass, field
from typing import Any, Optional, BinaryIO

class MediaType(str, Enum):
    IMAGE = "image"
    VIDEO = "video"
    AUDIO = "audio"
    PDF   = "pdf"       # 已有文档摘要工作流可复用

class MediaSource(str, Enum):
    LOCAL  = "local"    # 本地文件路径
    URL    = "url"      # HTTP(S) URL
    BASE64 = "base64"   # Base64 编码字符串
    BYTES  = "bytes"    # 内存中的 bytes

@dataclass
class MediaFile:
    """多媒体文件抽象。

    任何一个 Task 拿到的都是这个统一对象。
    内部延迟加载——只在真正需要时解码。
    """
    media_type: MediaType
    source_type: MediaSource
    source: str | bytes               # path / URL / base64 / raw bytes
    metadata: dict[str, Any] = field(default_factory=dict)

    # 以下字段延迟加载
    _raw_bytes: Optional[bytes] = field(default=None, repr=False)
    _base64: Optional[str] = field(default=None, repr=False)

    async def to_bytes(self) -> bytes:
        """统一获取原始二进制数据。"""
        ...

    async def to_base64(self) -> str:
        """统一获取 base64 编码（给多模态 API 用）。"""
        ...

    @property
    def extension(self) -> str:
        """推断文件扩展名。"""
        ...

    @property
    def mime_type(self) -> str:
        """推断 MIME 类型。"""
        ...
```

### 5.3 处理器接口

```python
# icore/media/processors.py

class BaseMediaProcessor(ABC):
    """多媒体处理器抽象基类。

    每种媒体类型一个处理器。TaskContext 注入：
        ctx.get_media_processor() → 根据 MediaType 自动路由
    """

    @abstractmethod
    async def extract_metadata(self, file: MediaFile) -> dict[str, Any]:
        """提取元信息（分辨率、时长、采样率、EXIF 等）。"""
        ...

    @abstractmethod
    async def transcode(
        self, file: MediaFile, target_format: str
    ) -> MediaFile:
        """格式转码（如视频转关键帧、音频转 16kHz WAV）。"""
        ...

    @abstractmethod
    async def generate_thumbnail(
        self, file: MediaFile, size: tuple[int, int] = (256, 256)
    ) -> MediaFile:
        """生成缩略图。"""
        ...


class ImageProcessor(BaseMediaProcessor):
    """图片处理器：Pillow + OpenCV。"""
    async def ocr(self, file: MediaFile, lang: str = "chi_sim") -> str:
        """OCR 文字识别（PaddleOCR / easyocr）。"""
        ...


class VideoProcessor(BaseMediaProcessor):
    """视频处理器：ffmpeg-python / moviepy。

    - 提取关键帧（每秒 N 帧）
    - 提取音频轨道
    - 转码兼容格式
    """
    async def extract_keyframes(
        self, file: MediaFile, fps: int = 1
    ) -> list[MediaFile]:
        """按帧率提取关键帧列表。"""
        ...

    async def extract_audio_track(self, file: MediaFile) -> MediaFile:
        """提取音频轨道。"""
        ...


class AudioProcessor(BaseMediaProcessor):
    """音频处理器：pydub / librosa / whisper。

    - 转码（统一 16kHz mono WAV）
    - 语音转文字（ASR，内部调用 whisper adapter 或 API）
    - 说话人分离（speaker diarization）
    """
    async def transcribe(
        self, file: MediaFile, language: str = "zh"
    ) -> str:
        """语音转文字。"""
        ...

    async def split_by_silence(
        self, file: MediaFile, min_silence_len: int = 500
    ) -> list[MediaFile]:
        """按静音片段切分。"""
        ...
```

## 6. 多模态模型适配

### 6.1 设计动机

- v0.4 的 `BaseModelAdapter` 只定义了 `chat()` / `embed()` / `stream_chat()`，全都是纯文本
- 需要扩展 adapter 使其能处理图片输入（base64 / URL），为视频帧和音频转文字后的分析铺路
- 支持 GPT-4V、Claude 3.5 Vision、Gemini Pro Vision、Qwen-VL 等多模态模型

### 6.2 接口扩展

```python
# icore/models/base_adapter.py（扩展）

class BaseModelAdapter(ABC):
    # === v0.4 已有 ===
    async def chat(self, messages, **kwargs) -> dict: ...
    async def embed(self, texts) -> list[list[float]]: ...
    def stream_chat(self, messages, **kwargs) -> AsyncIterator[str]: ...
    async def health_check(self) -> bool: ...
    async def close(self) -> None: ...

    # === v0.5 新增 ===

    @property
    def supports_vision(self) -> bool:
        """是否支持视觉输入。默认 False。"""
        return False

    @property
    def supports_audio(self) -> bool:
        """是否支持音频输入（如 GPT-4o-audio）。默认 False。"""
        return False

    async def chat_with_media(
        self,
        prompt: str,
        media_files: list[MediaFile],
        **kwargs,
    ) -> dict[str, Any]:
        """带多模态输入的对话。

        Args:
            prompt:      用户的文本提示
            media_files: 多媒体文件列表（图片 / 视频帧 / 音频）
            **kwargs:    额外参数透传给 API

        Returns:
            {"content": str, "usage": {...}, "model": str, ...}

        Raises:
            NotImplementedError: 如果模型不支持（supports_vision = False）
        """
        if not self.supports_vision:
            raise NotImplementedError(
                f"Model '{self.model_id}' does not support vision input"
            )
        ...

    async def embed_multimodal(
        self,

    ) -> list[list[float]]:
        """多模态 Embedding（如 CLIP 的图文对齐向量）。

        纯文本模型降级为标准 embed()，多模态模型可对齐图文向量。
        """
        # 默认：分离文本和媒体，纯文本部分用 embed()
        ...
```

### 6.3 Vision 适配器实现（以 GPT-4V 为例）

```python
# icore/models/vision_adapter.py

class VisionModelAdapter(OpenAICompatibleAdapter):
    """多模态视觉模型适配器。

    继承 OpenAICompatibleAdapter，新增 vision 能力。
    支持 GPT-4V / GPT-4o / Claude 3.5 Sonnet / Gemini Pro Vision。
    """

    @property
    def supports_vision(self) -> bool:
        return True

    async def chat_with_media(
        self,
        prompt: str,
        media_files: list[MediaFile],
        **kwargs,
    ) -> dict[str, Any]:
        """构建多模态 messages 并发给 API。

        OpenAI Vision API 格式：
        {
            "role": "user",
            "content": [
                {"type": "text", "text": prompt},
                {"type": "image_url",
                 "image_url": {"url": "data:image/jpeg;base64,..."}}
            ]
        }

        Claude Vision 格式（自动适配 provider）：
        使用 images 字段传递 base64。
        """
        content: list[dict] = [{"type": "text", "text": prompt}]
        for mf in media_files:
            if mf.media_type == MediaType.IMAGE:
                b64 = await mf.to_base64()
                content.append({
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:{mf.mime_type};base64,{b64}",
                        "detail": kwargs.pop("image_detail", "auto"),
                    },
                })
            elif mf.media_type == MediaType.VIDEO:
                # 视频：自动提取关键帧后再送入
                # （由 VideoProcessor 预处理，不应在此处理）
                raise ValueError(
                    "Video files must be pre-processed into frames. "
                    "Use VideoProcessor.extract_keyframes() first."
                )
            elif mf.media_type == MediaType.AUDIO:
                raise ValueError(
                    "Audio files must be transcribed first. "
                    "Use AudioProcessor.transcribe() then pass text."
                )

        # 复用父类 chat()，但 messages content 是 list（非 pure string）
        messages = [{"role": "user", "content": content}]
        return await self.chat(messages, **kwargs)
```

### 7.2 模型返回异常处理（熔断 / 降级 / 重试）

#### 7.2.1 熔断器模式

```python
# icore/engine/circuit_breaker.py

from enum import Enum
from dataclasses import dataclass, field
import time, asyncio, logging

logger = logging.getLogger(__name__)

class CircuitState(str, Enum):
    CLOSED       = "closed"       # 正常通行
    OPEN         = "open"         # 熔断中，拒绝请求
    HALF_OPEN    = "half_open"    # 试探性恢复

@dataclass
class CircuitBreaker:
    """熔断器 — 每个模型适配器一个实例。

    状态转移：
        CLOSED ── 连续失败 >= failure_threshold ──► OPEN
        OPEN   ── 等待 timeout 秒后 ──► HALF_OPEN
        HALF_OPEN ── 试探成功 ──► CLOSED
        HALF_OPEN ── 试探失败 ──► OPEN
    """

    name: str                           # 通常是 model_id
    failure_threshold: int = 5          # 连续失败 N 次 → 熔断
    recovery_timeout: float = 30.0      # 熔断后等 N 秒 → 半开
    half_open_max_requests: int = 3     # 半开状态下允许的试探请求数

    state: CircuitState = CircuitState.CLOSED
    failure_count: int = 0
    last_failure_time: float = 0.0
    half_open_successes: int = 0
    half_open_failures: int = 0

    _lock: asyncio.Lock = field(default_factory=asyncio.Lock)

    async def call(self, coro_factory):
        """执行受保护的异步调用。"""
        await self._pre_call()
        try:
            result = await coro_factory()
            await self._on_success()
            return result
        except Exception as e:
            await self._on_failure()
            raise e

    async def _pre_call(self):
        async with self._lock:
            if self.state == CircuitState.OPEN:
                if time.time() - self.last_failure_time >= self.recovery_timeout:
                    self.state = CircuitState.HALF_OPEN
                    self.half_open_successes = 0
                    self.half_open_failures = 0
                    logger.info("Circuit '%s' → HALF_OPEN", self.name)
                else:
                    raise CircuitBreakerOpenError(
                        f"Circuit breaker for '{self.name}' is OPEN"
                    )

    async def _on_success(self):
        async with self._lock:
            if self.state == CircuitState.HALF_OPEN:
                self.half_open_successes += 1
                if self.half_open_successes >= self.half_open_max_requests:
                    self.state = CircuitState.CLOSED
                    self.failure_count = 0
                    logger.info("Circuit '%s' → CLOSED", self.name)
            elif self.state == CircuitState.CLOSED:
                self.failure_count = 0

    async def _on_failure(self):
        async with self._lock:
            self.failure_count += 1
            self.last_failure_time = time.time()
            if self.state == CircuitState.HALF_OPEN:
                self.half_open_failures += 1
                self.state = CircuitState.OPEN
                logger.warning("Circuit '%s' → OPEN (half-open fail)", self.name)
            elif (
                self.state == CircuitState.CLOSED
                and self.failure_count >= self.failure_threshold
            ):
                self.state = CircuitState.OPEN
                logger.warning(
                    "Circuit '%s' → OPEN (%d failures)", self.name, self.failure_count
                )
```

#### 7.2.2 模型调用降级策略

```python
# icore/models/manager.py（扩展）

class ModelManager:
    async def call_with_fallback(
        self,
        model_id: str | None,
        fn: Callable,
        fallback_model_ids: list[str] | None = None,
    ) -> Any:
        """带降级的模型调用。

        1. 通过熔断器检查主模型
        2. 主模型失败 → 按 fallback_model_ids 列表依次尝试
        3. 全部失败 → 抛出 NoAvailableModelError
        """
        cb = self._get_circuit_breaker(model_id or self._default_model_id)
        try:
            return await cb.call(lambda: fn(self.get_adapter(model_id)))
        except CircuitBreakerOpenError:
            logger.warning("Circuit breaker open for '%s'", model_id)
        except (ModelAPIError, ModelTimeoutError):
            logger.warning("Model '%s' failed, trying fallback", model_id)

        # 降级链
        for fb_id in (fallback_model_ids or []):
            adapter = self.get_adapter(fb_id)
            cb = self._get_circuit_breaker(fb_id)
            try:
                return await cb.call(lambda: fn(adapter))
            except Exception:
                continue

        raise NoAvailableModelError("All models exhausted")
```

### 7.3 冲突解决（分布式锁 / 乐观锁 / 幂等）

#### 7.3.1 设计动机

- 需要分布式锁保证写操作的原子性

#### 7.3.2 分布式锁

```python
# icore/engine/lock.py

from abc import ABC, abstractmethod
from contextlib import asynccontextmanager
from typing import AsyncIterator

class BaseDistributedLock(ABC):
    """分布式锁抽象。"""

    @abstractmethod
    async def acquire(
        self, key: str, ttl: float = 30.0, blocking: bool = True
    ) -> bool:
        """获取锁。返回 True 表示获取成功。"""
        ...

    @abstractmethod
    async def release(self, key: str) -> None:
        """释放锁。"""
        ...

    @asynccontextmanager
    async def lock(
        self, key: str, ttl: float = 30.0
    ) -> AsyncIterator[None]:
        """上下文管理器用法。

        async with ctx.get_lock().lock("graph:upsert:task-123"):
            await graphstore.upsert_nodes(nodes)
        """
        try:
            acquired = await self.acquire(key, ttl)
            if not acquired:
                raise ConflictError(f"Failed to acquire lock: {key}")
            yield
        finally:
            await self.release(key)


class RedisLock(BaseDistributedLock):
    """基于 Redis 的分布式锁。

    使用 SET NX + PX 实现带过期时间的锁。
    每次 acquire 生成一个随机 token，release 时校验（防误解锁）。
    """
    LUA_RELEASE = '''
        if redis.call("GET", KEYS[1]) == ARGV[1] then
            return redis.call("DEL", KEYS[1])
        else
            return 0
        end
    '''


class MemoryLock(BaseDistributedLock):
    """单进程内存锁（asyncio.Lock，用于开发环境无需 Redis）。"""
```
